# Dwarpal v1.0.1

Dwarpal 1.0.1 is a bug-fix release for the app-lock and recovery flows reported after 1.0.0.

## Highlights

### Unlocking works reliably

- The PIN pad and password field now have an explicit **Unlock / Confirm** button; physical
  **Enter** works from the PIN field, the password field or any other focused control.
- On a successful credential the lock window closes immediately and every suspended process in that
  app's session is resumed. A slow audit-log write can no longer leave the lock screen hanging over
  an already-unlocked app.
- Chrome, Discord and other multi-process apps get **one lock screen per app**. Child processes join
  the same session instead of opening extra windows, and all of them resume together.

### The lock screen is usable again

- The full-screen topmost overlay is replaced by a compact 520 × 720 PIN window.
- The taskbar entry is visible while an app is locked, and other applications remain usable.
- Closing the lock window with the taskbar still cannot bypass it; only a valid credential (or the
  protected app exiting) closes the session.

### Recovery and lockout

- Resetting the credential from the **Forgot PIN or password?** flow now clears any active lockout
  countdown as well as the persisted lockout state. The new PIN/password is accepted immediately.
- The recovery window only shows its success message after the reset actually completed.

### Protection cannot be skipped at startup

- The protection engine now starts before the startup unlock gate, so launching a protected app
  while the gate is visible still locks it.
- The startup gate can no longer be closed to exit Dwarpal without the credential. A Windows
  shutdown still closes it cleanly; the gate can be minimized from its own button or the taskbar.

### Other fixes

- Auto-start now quotes the executable path passed to `schtasks /TR`, fixing task creation when
  Dwarpal is installed under `Program Files`.
- Settings checkboxes revert correctly when Task Scheduler or selfie changes fail.
- The dashboard shows the real active profile and enabled-app count.
- Editing an inactive profile no longer locks apps from the active profile.
- Failed screen captures or icon extraction no longer risk leaving a suspended app behind.
- Profile selection counts, app-picker search selection, schedule/app toggle failures and recovery
  messages now reflect their real state.

## Install

- **Installer:** `Dwarpal-Setup-1.0.1.exe` — per-machine, elevated. The bundled .NET 8 Desktop
  Runtime (x64) is installed automatically when it is missing; no browser or download page is used.
- **Portable:** `Dwarpal-1.0.1-portable.zip` — extract anywhere and run `Dwarpal.exe`. Data still
  lives in `%ProgramData%\Dwarpal`.

Verify downloads with `SHA256SUMS.txt` attached to the release.

## Verification

- `dotnet build Dwarpal.sln --configuration Release` passes with 0 warnings and 0 errors.
- 87 Core unit tests pass, including a new regression test that resets the credential with a recovery
  key while a lockout is active and verifies the new credential is accepted immediately.
- Installer and portable ZIP are rebuilt from the 1.0.1 sources; checksums are generated by the
  release workflow.

## Known limitations

- The binaries are not code-signed. Windows SmartScreen may warn on first run.
- The protection suite remains a user-mode app locker; see the README's "Known limitations" section
  for the complete list.
